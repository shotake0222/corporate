## 1. しくみ（3行で）

1. 記事は **Markdown（.md）という形式のテキストファイル** で、1記事＝1ファイルです。
2. ファイルを GitHub の決まったフォルダに置く（＝コミットする）と、
3. Cloudflare が自動でサイトを作り直し、**1〜3分ほどで公開** されます。

| 種類 | ファイルを置くフォルダ | 公開される URL |
| --- | --- | --- |
| ニュース | `src/content/news/` | `/news/ファイル名/` |
| ブログ | `src/content/blog/` | `/blog/ファイル名/` |

トップページには、ニュースは新しい順に **5件**、ブログは **3件** が自動で表示されます。一覧ページには全件が並びます。

## 2. ニュースを追加する

### 手順

1. https://github.com/shotake0222/corporate/tree/main/src/content/news を開く
2. 右上の **「Add file」→「Create new file」** を押す
3. 上部の「Name your file...」欄に **ファイル名** を入力する
   - 形式：`日付-英数字の名前.md`
   - 例：`2026-12-01-new-service.md`
4. 本文欄に、次の内容を貼り付けて書き換える

   ```markdown
   ---
   title: 新サービス提供開始のお知らせ
   date: 2026-12-01
   category: プレスリリース
   ---

   平素より格別のご高配を賜り、厚く御礼申し上げます。

   本文をここに書きます。空行をはさむと段落が分かれます。

   ## 概要

   - サービス名：○○○
   - 提供開始日：2026年12月1日
   ```

5. 右上の **「Commit changes...」** を押す
6. 出てきた画面の「Commit message」に変更内容（例：`ニュース追加：新サービス提供開始`）を書き、**「Commit changes」** を押す
7. 1〜3分待ってから公開 URL を開いて確認する（→ [7. 公開されたか確認する](#7-公開されたか確認する)）

### ファイル名のルール

- **半角の英小文字・数字・ハイフン（-）だけ** を使う（日本語・スペース・記号は使わない）
- 先頭は `YYYY-MM-DD-`（公開日）にしておくと、並び順の管理がしやすくなります
- ファイル名がそのまま URL になります。**公開後に変えると URL が変わる** ので注意してください
- `_`（アンダーバー）で始まるファイルは公開されません（`_template.md` はひな形です）

### カテゴリの例

`category` は一覧に出るラベルです。自由に書けますが、表記をそろえると見た目が整います。

| 用途 | 例 |
| --- | --- |
| 一般的なお知らせ | `お知らせ`（省略時はこれになります） |
| 報道発表 | `プレスリリース` |
| 新サービス・機能 | `サービス` |
| 掲載・受賞 | `メディア掲載` |
| イベント | `イベント` |

## 3. ブログを追加する

手順はニュースと同じで、**フォルダが違うだけ** です。

1. https://github.com/shotake0222/corporate/tree/main/src/content/blog を開く
2. 「Add file」→「Create new file」
3. ファイル名を入力（例：`2026-12-05-why-we-started.md`）
4. 次の内容を貼り付けて書き換える

   ```markdown
   ---
   title: 私たちがこの事業を始めた理由
   date: 2026-12-05
   category: 会社のこと
   description: 一覧・検索結果・SNSに表示される要約です。80〜120文字くらいが目安です。
   ---

   書き出しの段落です。

   ## 最初の見出し

   本文です。
   ```

5. 「Commit changes...」→「Commit changes」

### ブログのサムネイル

**何もしなくても、タイトル・日付・カテゴリ・ロゴ入りのサムネイル画像が自動で作られます。**
この画像は、ブログ一覧のカードと、SNS（X・Facebook など）で共有されたときの画像の両方に使われます。

写真などを使いたい場合だけ、次のようにします。

1. 画像を `public/images/blog/` に置く（→ [5. 画像を入れる](#5-画像を入れる)）
2. フロントマターに 1 行追加する

   ```markdown
   thumbnail: /images/blog/2026-12-05-cover.jpg
   ```

- 推奨サイズは **横1200 × 縦630 ピクセル**（この比率で一覧に表示されます）
- `thumbnail` を指定した記事は、記事ページの先頭にもその画像が表示されます

### ニュースとブログの使い分け（目安）

| ニュース | ブログ |
| --- | --- |
| 会社として「事実」を知らせる | 考え・背景・ノウハウを「読み物」として届ける |
| プレスリリース、新サービス、掲載、休業日など | 事業の背景、サービスの裏話、コラム |
| 短め・定型 | 長め・見出しを使って構成 |

## 4. 記事の書き方ルール

### 4-1. ファイルの構成

```markdown
---              ← フロントマター（記事の設定）の始まり
title: タイトル
date: 2026-12-01
category: お知らせ
---              ← フロントマターの終わり

ここから本文。
```

- `---` は **半角ハイフン3つ** で、上下2行とも必要です
- `title:` のように **項目名のあとは「半角コロン＋半角スペース」**

### 4-2. フロントマターの項目

**すべて省略できます**（省略したときの動きは右端の列）。

| 項目 | 意味 | 書き方の例 | 省略した場合 |
| --- | --- | --- | --- |
| `title` | 記事タイトル | `title: 新サービスのお知らせ` | 本文1行目の `# 見出し` → それも無ければファイル名 |
| `date` | 公開日（並び順にも使う） | `date: 2026-12-01` | ファイル名先頭の日付 |
| `category` | 一覧に出るラベル | `category: プレスリリース` | ニュースは「お知らせ」、ブログは「ブログ」 |
| `description` | 一覧・検索結果・SNS に出る要約 | `description: ○○を開始しました。` | 本文の冒頭から自動で作成 |
| `thumbnail` | サムネイル画像 | `thumbnail: /images/blog/cover.jpg` | タイトル入り画像を自動作成 |
| `draft` | 下書き（`true` の間は公開しない） | `draft: true` | 公開する |

### 4-3. タイトル（h1）について

- 記事タイトルはページ上で **一番大きな見出し（h1）** として表示されます
- 書き方は次の **どちらでも同じ結果** になります

  **A. フロントマターに書く（おすすめ）**

  ```markdown
  ---
  title: はじめまして
  date: 2026-12-01
  ---

  本文です。
  ```

  **B. 本文の1行目に `#` で書く**

  ```markdown
  # はじめまして

  本文です。
  ```

  B の場合、その行は本文からは自動で取り除かれ、タイトルとして使われます（ファイル名が `2026-12-01-hello.md` なら日付も自動で入ります）。

- **本文中では `#`（h1）を使わず、`##` と `###` を使ってください。** `#` は記事タイトル専用です

### 4-4. タイトルに記号を含むとき

タイトルに **「: 」（コロン＋スペース）** が入る場合や、`"` `'` `[` `#` などの記号で **始まる** 場合は、全体を `"` で囲みます。

```markdown
title: "お知らせ: 年末年始の営業について"
```

全角の「：」や、文中の `'`（例：`in One's`）はそのままで問題ありません。

### 4-5. 本文の書き方（早見表）

| やりたいこと | 書き方 | 表示 |
| --- | --- | --- |
| 段落を分ける | 空行を1行入れる | 段落になる |
| 大見出し | `## 見出し` | 下線付きの見出し |
| 小見出し | `### 見出し` | 左線付きの見出し |
| 太字 | `**強調したい文字**` | 太字＋薄い下線 |
| リンク | `[表示する文字](https://example.com)` | 外部サイトは自動で別タブ |
| サイト内リンク | `[お問い合わせ](/contact/)` | 同じタブで移動 |
| 箇条書き | `- 項目` | ・項目 |
| 番号付き | `1. 項目` | 1. 項目 |
| 引用・補足 | `> 文章` | 背景色付きの囲み |
| 画像 | `![説明](/images/news/photo.jpg)` | 画像 |
| 区切り線 | `---`（前後に空行） | 横線 |
| 表 | 下の例を参照 | 表 |

表の書き方：

```markdown
| 項目 | 内容 |
| --- | --- |
| 日時 | 2026年12月1日（月）10:00〜 |
| 場所 | オンライン |
```

> 記法の見本をまとめた記事が `src/content/blog/sample-markdown.md` にあります（`draft: true` なので本番には表示されません）。

## 5. 画像を入れる

### 手順（GitHub の画面で）

1. 画像の置き場所を開く
   - ニュース用：https://github.com/shotake0222/corporate/tree/main/public/images/news
   - ブログ用：https://github.com/shotake0222/corporate/tree/main/public/images/blog
2. 「Add file」→ **「Upload files」**
3. 画像をドラッグ＆ドロップ（または「choose your files」から選択）
4. 「Commit changes」を押す
5. 記事の本文に次のように書く（`public` は書かない）

   ```markdown
   ![新サービスの画面](/images/news/2026-12-01-service.jpg)
   ```

### 画像のルール

| 項目 | 目安 |
| --- | --- |
| ファイル名 | 半角英小文字・数字・ハイフンのみ（例：`2026-12-01-service.jpg`）。記事と同じ日付を頭に付けると管理が楽です |
| 形式 | 写真は JPG または WebP、図やロゴは PNG |
| 大きさ | 横幅 1600px 以下、1枚 500KB 以下を目安（大きいと表示が遅くなります） |
| 説明文 | `![ここ]` の部分に内容を書く（読み上げ・検索に使われます） |

> 記事と画像を同時に追加するときは、**先に画像をアップロード** してから記事を作ると、公開直後から画像が表示されます。

## 6. 記事を直す・下書きに戻す・消す

### 直す

1. GitHub で該当のファイルを開く
2. 右上の **鉛筆アイコン（Edit this file）** を押す
3. 修正して「Commit changes...」→「Commit changes」

### 下書きに戻す（一時的に非公開にする）

フロントマターに `draft: true` を追加してコミットします。公開に戻すときはその行を消します（または `false`）。

```markdown
---
title: ○○○
date: 2026-12-01
draft: true
---
```

### 公開前に下書きとして置いておく

最初から `draft: true` を付けて作成すれば、GitHub には保存されますが本番には出ません。準備ができたら `draft: true` の行を消してコミットします。

### 消す

1. GitHub で該当のファイルを開く
2. 右上の「…」→ **「Delete file」**
3. 「Commit changes」

> 記事を消しても、使っていた画像は残ります。不要なら画像も同じ手順で削除してください。

## 7. 公開されたか確認する

1. コミットしてから **1〜3分** 待つ
2. 公開 URL を開いて確認する（ブラウザの再読み込みをしても古いときは、もう少し待つ）
   - ニュース一覧：https://corporate.straid-nfc-companion.workers.dev/news/
   - ブログ一覧：https://corporate.straid-nfc-companion.workers.dev/blog/
3. 反映されないときは、Cloudflare でビルドの状態を見る
   - https://dash.cloudflare.com →「Workers & Pages」→ `corporate` →「デプロイ（Deployments）」→ ビルド履歴
   - **成功**：しばらく待てば反映されます
   - **失敗**：ビルドを開いてログを確認（→ [8. うまくいかないとき](#8-うまくいかないとき)）
   - **ビルド自体が無い**：自動ビルドが動いていません。同じ画面から最新の `main` を手動でビルドするか、管理者（Claude など）に連絡してください

## 8. うまくいかないとき

ビルドが「失敗」になった場合、**サイトは直前の状態のまま** 表示され続けます（壊れた状態で公開されることはありません）。原因を直して再度コミットすれば復旧します。
ログには、多くの場合 **問題のあるファイル名**（例：`news/2026-12-01-xxx.md`）が表示されます。

| 症状 | よくある原因 | 直し方 |
| --- | --- | --- |
| ビルド失敗。ログに「日付がありません」 | `date` が無く、ファイル名も日付で始まっていない | `date: 2026-12-01` を追加する |
| ビルド失敗。ログに `Nested mappings are not allowed` などの英文と、問題のファイル名・行番号 | フロントマターの書き方の誤り（多いのはタイトル中の「: 」） | タイトルに「: 」が入っていれば `"` で囲む（→ [4-4](#4-4-タイトルに記号を含むとき)）。`---` が上下にあるか、`項目名: 値` の「: 」が半角かも確認 |
| ビルド失敗。ログに `does not match collection schema` と `date` | 日付の形式が違う（`2026/12/01` など） | `2026-12-01` の形（年-月-日、半角ハイフン）にする |
| 記事が出てこない | `draft: true` が付いている | その行を消す |
| 記事が出てこない | フォルダが違う／ファイル名が `_` で始まる／拡張子が `.md` でない | 置き場所とファイル名を確認する |
| 並び順がおかしい | `date` の書き間違い | 日付を確認する |
| 画像が表示されない | パスの間違い（`public` を書いている、大文字小文字の違い、拡張子の違い） | `/images/news/ファイル名.jpg` の形で、ファイル名を一字一句そろえる |
| 本文中にタイトルと同じ大きさの見出しが出る | 本文の途中で `#` を使っている | 本文中の見出しは `##` / `###` にする |
| 太字やリンクにならない | 記号が全角になっている | `**` `[` `]` `(` `)` を半角にする |

## 9. そのほかの更新場所

ニュース・ブログ以外の文言を変える場合は、次のファイルを編集します（GitHub の鉛筆アイコンで編集可能）。

| 変えたいもの | ファイル |
| --- | --- |
| メインビューのメッセージ、ミッション、ビジョン | `src/data/site.ts`（`hero` / `mission` / `vision`） |
| 代表メッセージ | `src/content/pages/message.md` |
| 代表者のポートフォリオ・SNS のリンク | `src/data/site.ts`（`representative`） |
| 会社概要（設立日・所在地・資本金・事業内容など） | `src/data/site.ts`（`company`）。`value: ''` の項目は「準備中」と表示 |
| メディア掲載 | `src/data/media.ts`（ロゴ画像は `public/images/media/`） |
| サービス一覧 | `src/data/services.ts`（ロゴ画像は `public/images/service/`） |
| 個人情報保護方針／サイトポリシー | `src/content/pages/privacy.md` ／ `policy.md` |

> `.ts` ファイルは書き方が少し厳密です（`'` や `,` を消すとビルドが失敗します）。**文字の中身だけを書き換える** ようにしてください。

### メディア掲載のリンクを PDF に差し替える

1. PDF を `public/pdf/` にアップロード（例：`magazine-summit.pdf`）
2. `src/data/media.ts` の該当行の `url` を `'/pdf/magazine-summit.pdf'` に書き換える

### 会社ロゴの画像データ

資料・名刺などに使うロゴの PNG は `brand/logo/` にあります（サイトには公開されません）。

| ファイル | 内容 |
| --- | --- |
| `in-ones-logo-stacked-*.png` | シンボル＋「in One's」（縦組み） |
| `in-ones-logo-horizontal-*.png` | シンボル＋「in One's」（横組み） |
| `in-ones-logo-mark-*.png` | シンボルのみ |

`-transparent` が背景透過、`-white-bg` が白背景です。
